## Windows / PowerShell execution rules (apply to EVERY command step)

- Shell is PowerShell: chain with `;` (NOT `&&`); set env inline as `$env:VAR="..."` before a command when needed.
- Do NOT rely on `npx` or `.ps1` bin shims (execution-policy may block them). Invoke node CLIs directly:
  - Prisma: `node node_modules/prisma/build/index.js <cmd>`
  - tsx (seed): `node node_modules/tsx/dist/cli.mjs prisma/seed.ts`
  - tsc: `node node_modules/typescript/bin/tsc --noEmit`
- Do NOT start long-running processes (`next dev`, watchers) in any automated step — a running `next dev`
  can lock the Prisma engine DLL and cause `EPERM` on `generate`. None is running now; keep it that way.
- The committed npm scripts (added in step 8) are developer-shell INTENT; automation uses the node-CLI forms above.

## Notes, assumptions, and gaps

- **zod**: the step brief lists zod among Phase 1 deps, but the LOCKED design's Phase 1 dependency table
  places zod in later phases and installs only `@prisma/client`, `bcryptjs`, `prisma`, `tsx`,
  `@types/bcryptjs`. The design is the contract, so zod is NOT installed in Phase 1 (step 2). Recorded as a
  deliberate deviation; if a later reviewer insists zod belongs in Phase 1, it is a one-line add.
- **CHECK-constraint application mechanism** (step 10c): `migrate dev` marks the migration applied before the
  CHECKs are appended, so the appended SQL must reach the live DB somehow. The plan prefers
  `migrate reset --force` on this fresh, dataless DB because it re-runs the exact committed migration.sql
  (CHECKs included) and keeps the committed SQL and the live schema identical. A `db execute` of just the two
  ALTERs is the fallback if reset is undesirable. Either way the acceptance proof is "both CHECK constraints
  exist in the live DB".
- **`.env.example` and git**: `.gitignore` has `.env*`, which also matches `.env.example`. The design states
  `.env.example` IS committed. The coder should create it regardless; whether it is force-added to git is a
  later-commit concern and this phase makes NO commits.
- No `src/` directory is created anywhere; all code is root-level (`lib/`, `prisma/`). `next.config.ts`,
  `tsconfig.json`, and `app/` are left untouched except where a step explicitly edits a file.
